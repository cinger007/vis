5.1 时间属性

时间有 5 个核心属性：有序 / 连续 / 周期 / 独立于空间 / 结构性。每个属性都影响可视化设计。

Time has 5 core properties: ordered / continuous / cyclic / independent of space / structural. Each property shapes visualization design.

你的原案例

Your Original Case

原 6.1 节列出 5 个时间属性，没有可视化。这章把这 5 个属性变成可交互卡片。

Original section 6.1 listed the 5 time properties without any visualization. This chapter turns those 5 properties into interactive cards.

嵌入陈为教材理论

Embedding Chen Wei's Textbook Theory

  • 有序性：时间是有序的，两个事件有先后次序，与因果关系紧密相连。
  • Order: Time is ordered—any two events have a before/after, tightly linked to causality.
  • 连续性：时间连续，两个时间点之间总存在另一个时间点。
  • Continuity: Time is continuous—between any two moments there is always another moment.
  • 周期性：自然过程常有循环规律（季节、昼夜），可采用循环时间域。
  • Periodicity: Natural processes often follow cyclic patterns (seasons, day/night)—a cyclic time domain can be used.
  • 独立于空间：时间与空间紧相关，但科学过程大多独立处理。
  • Independence from space: Time is tightly coupled with space, but scientific processes usually treat them independently.
  • 结构性：时间尺度分年/月/日/时/分/秒，分割既有自然反映（昼夜）也有人为定义（60 秒）。
  • Structure: Time scales split into year / month / day / hour / minute / second—some divisions reflect nature (day/night), others are human convention (60 seconds).

为什么 5 个属性都重要？

Why do all 5 properties matter?

设计时序图前先想清楚这 5 个属性，能避免常见错误：

Thinking through these 5 properties before designing a time series chart avoids common pitfalls:

  • 有序性缺失 → 散点图错位成噪声
  • Missing order → scatter plot misaligned into noise
  • 连续性混淆 → 离散数据用错连线
  • Confused continuity → discrete data wrongly connected
  • 周期性忽略 → 季节趋势被"抹平"
  • Ignored periodicity → seasonal trends “flattened out”
  • 结构性不匹配 → 工作日/周末、闰年都出错
  • Mismatched structure → weekdays/weekends, leap years all go wrong

5.2 标准时间可视化（折线图）

x 轴 = 时间，y 轴 = 度量。最常见的时序图：法国人名 1900-2020 的使用频率。

x-axis = time, y-axis = measure. The most common time series chart: frequency of French names from 1900–2020.

Your Original Case

原 6.2.1 节用折线图展示法国几十年人名（Marie / Jean / Camille）的使用频率变化。
原始页面附带"词云 + 鼠标高亮 + 时间段筛选"，但代码只给了关键折线段。

Original section 6.2.1 used line charts to show usage-frequency changes of French names (Marie / Jean / Camille) over decades.

嵌入陈为教材理论

Embedding Chen Wei's Textbook Theory

  • 标准时序图本质：二维线图，x = 时间，y = 度量。优势是在线性时间域中的变化趋势一目了然。
  • Essence of the standard time series chart: a 2D line chart with x = time, y = measure. The advantage is that change trends in a linear time domain are immediately clear.
  • 缺点：难以表达周期性——所以才有了 5.3 日历图和 5.4 螺旋图。
  • Drawback: hard to express periodicity—hence section 5.3 calendar heatmap and section 5.4 spiral.
  • 交互：鼠标 hover 高亮、tip 显示、筛选时间段——是数据新闻标配。
  • Interaction: hover highlight, tooltip, time-range filtering—the data-journalism standard.
  • 实战选择：数据点数 ≤ 50 用 linear；点数 50-500 用 monotoneX / curveCatmullRom；点数 > 500 才考虑面积 / 箱形。
  • Choosing in practice: ≤50 points use linear; 50–500 use monotoneX / curveCatmullRom; >500 consider area / box plot.

⭐ 关键点 3：hover 高亮 + tip

⭐ Key Point 3: hover highlight + tooltip

// 透明覆盖层捕获鼠标事件
const focus = svg.append('g').style('display', 'none');
focus.append('line')             // 垂直参考线
  .attr('class', 'hover-line')
  .attr('y1', 0).attr('y2', innerH);
focus.append('circle')           // 圆点
  .attr('r', 5).attr('fill', 'steelblue');
focus.append('text')             // tip
  .attr('class', 'tip');

svg.append('rect')               // 覆盖矩形
  .attr('width', innerW).attr('height', innerH)
  .attr('fill', 'none').attr('pointer-events', 'all')
  .on('mouseover', () => focus.style('display', null))
  .on('mouseout',  () => focus.style('display', 'none'))
  .on('mousemove', (event) => {
    const xm = d3.pointer(event)[0];
    const date = xScale.invert(xm - M.l);
    // bisect 找最近点
    const i = d3.bisector(d => d.year).left(series, date);
    const d = series[i];
    focus.attr('transform', `translate(${xScale(d.year)},0)`);
  });

⭐ 通用 hover 模板：透明矩形 + focus g（line + circle + text）。d3.bisector 找最近点比手写循环快且准。

⭐ Generic hover template: transparent rect + focus g (line + circle + text). d3.bisector finds the nearest point faster and more accurately than a hand-written loop.

5.3 日历热图（van Wijk）

以"年=行 / 周=列"展示全年数据，发现周期性 + 周内趋势 + 节假日异常。

Display a full year of data with “year = row / week = column”—reveal periodicity + weekly trends + holiday anomalies.

你的原案例

Your Original Case

原 6.2.2 节用日历热图展示 2024 年北京每日最高温度。每月之间用红线分隔。

Original section 6.2.2 used a calendar heatmap to show Beijing’s daily maximum temperature in 2024. Red lines separate each month.

嵌入陈为教材理论

Embedding Chen Wei's Textbook Theory

  • 日历热图 (Calendar Heatmap)：van Wijk 2008 提出，x = 周（年内的第几周），y = 星期几，颜色 = 数值。
  • Calendar Heatmap: proposed by van Wijk 2008, x = week (week-of-year), y = day of week, color = value.
  • 适用场景：长时序（年）+ 周期性（星期 / 月）+ 异常检测（节假日、工作日 vs 周末）。
  • Use cases: long time series (years) + periodicity (weekday / month) + anomaly detection (holidays, weekday vs weekend).
  • 设计要点：
    • 每周从周日（或周一）开始——影响"周末"在视觉上的位置
    • 月份之间用红线分隔——比 7×53 网格更易读
    • colormap 用顺序型（如 Viridis）——见 第 3 章 3.2 colormap
  • Design Considerations:
    • Each week starts on Sunday (or Monday)—this affects where the “weekend” sits visually
    • Separate months with red lines—more readable than a 7×53 grid
    • Use a sequential colormap (e.g., Viridis)—see Chapter 3 §3.2 Colormap

isMonthDivider 的巧妙之处

The cleverness of isMonthDivider

判断 7 天前与今天是否同月——是则同月分割线，否则需要画月线。这是日历可视化的核心算法。

Check whether 7 days ago and today are in the same month—if so, draw a same-month separator; otherwise draw a month-divider. This is the core algorithm of calendar visualization.

⭐ 关键代码

⭐ Key Code

⭐ 关键点 1：d3.timeDay.range + d3.timeFormat.isoDate

⭐ Key Point 1: d3.timeDay.range + d3.timeFormat.isoDate

// ⭐ 把"年"拆成"日"列表
const days = d3.timeDay.range(
  new Date(2024, 0, 1),         // 2024-01-01
  new Date(2025, 0, 1)          // 2025-01-01

  date:  d,

// 现在 days.length === 366（2024 闰年）

⭐ d3.timeDay.range(start, stop) 是"日内连续性 + 结构性"两个属性的合击——自动按日粒度切分整年，闰年 366 / 平年 365 自动正确。

⭐ d3.timeDay.range(start, stop) combines “intra-day continuity + structure”—it automatically slices a whole year by day, with leap-year 366 / common-year 365 handled correctly.

⭐ 关键点 2：周日为起点布局

⭐ Key Point 2: Sunday-first layout

function weekColSunday(date) {
  // 周日为每列起点 (getDay()=0)
  return Math.floor((d3.timeDay.count(
    d3.timeYear.floor(date), date)) / 7);
}
function dayIndexSunday(date) {
  return date.getDay();    // 0=周日, 1=周一, ..., 6=周六
}

// 渲染每个日格
g.selectAll('rect.cell')
  .data(days).join('rect')
  .attr('class', 'cell')
  .attr('width',  cellSize)
  .attr('height', cellSize)
  .attr('x', d => weekColSunday(d.date) * cellSize)
  .attr('y', d => dayIndexSunday(d.date) * cellSize)
  .attr('rx', 2).attr('ry', 2)
  .attr('fill', d => color(d.value));

⭐ 周日 vs 周一布局是日历热图的设计分歧：周日为起点是英文日历传统（2024-01-01 是周一，所在列第 1 行往下是 周一→周六，最末行是周日）。中文场景常改成周一起点。

⭐ Sunday vs Monday layout is a calendar heatmap design fork: Sunday-first is the English calendar convention (2024-01-01 is Monday, so in its column row 1 is Mon→Sat and the last row is Sun). Chinese settings often switch to Monday-first.

⭐ 关键点 3：isMonthDivider 月份分隔

⭐ Key Point 3: isMonthDivider month separation

// ⭐ 巧妙算法：判断 7 天前是否同月
function isMonthDivider(date) {
  const sevenDaysAgo = d3.timeDay.offset(date, -7);
  return date.getFullYear() !== sevenDaysAgo.getFullYear()
      || date.getMonth()    !== sevenDaysAgo.getMonth();
}
// 同月：不画分割线；跨月：画一条上边框

function isFirstDayOfMonth(date) {
  return date.getDay() !== 0         // 排除周日（被周列开头替代）
      && date.getMonth() > 0         // 排除一月（画上边框没意义）
      && date.getDate() === 1;
}

⭐ 不用循环"找每个月的第一天"，改用"7 天前是否同月"——简洁又正确，O(n) 一遍扫描即可。这是日历热图作者 van Wijk 的精妙算法。

⭐ Instead of looping to “find each month’s first day,” use “are 7 days ago and today in the same month?”—simple and correct, just an O(n) single-pass scan. This is the elegant algorithm from calendar heatmap author van Wijk.

5.4 周期时间可视化（阿基米德螺旋）

将时间沿圆周排列（螺旋 = 圆 + 持续展开）。发现周期性：每个回路 = 一个周期。

Place time along a circle (spiral = circle + continuous unwinding). Reveal periodicity: each loop = one cycle.

你的原案例

Your Original Case

原 6.2.3 节用阿基米德螺旋（等速螺旋）布局日期，每个回路代表 1 年 / 1 月 / 1 周。每个日期对应螺旋上的一个扇环。

Original section 6.2.3 used an Archimedean spiral (uniform-velocity spiral) to lay out dates, with each loop representing 1 year / 1 month / 1 week. Each date corresponds to a sector ring on the spiral.

嵌入陈为教材理论

Embedding Chen Wei's Textbook Theory

  • 螺旋 vs 折线：折线在线性时间域表现"趋势"，但难以表现"周期"；螺旋沿圆周重复，能突出周期性。
  • Spiral vs line: a line captures “trend” in a linear time domain but struggles with “cycle”; a spiral repeats around the circle, highlighting periodicity.
  • 阿基米德螺旋 (Archimedean Spiral)：r = a + bθ，等速展开（每转一圈半径增加常量 b）。
  • Archimedean Spiral: r = a + bθ, with uniform unwinding (radius increases by a constant b per revolution).
  • 动态 Δθ 算法：原文档的精妙点——Δθ = boxSize / √(b² + r²)，让每个扇环的弧长近似相等，保持视觉一致性。
  • Dynamic Δθ algorithm: the original document’s elegant move—Δθ = boxSize / √(b² + r²), which keeps each sector ring’s arc length roughly equal, preserving visual consistency.
  • 实战取舍：螺旋适合"年/季节/周"的循环，不适合"无周期"或"周期太长"。
  • Practical trade-offs: spirals suit “year / season / week” cycles, but are unsuitable when there is “no cycle” or “the cycle is too long”.

关键路径生成

Key Path Generation

每个日期对应螺旋上的一个扇环——4 个关键点：起点外/终点外/终点内/起点内，闭合回起点。

Each date maps to a sector ring on the spiral—4 key points: outer start / outer end / inner end / inner start, closing back to the start.

⭐ 关键代码

⭐ Key Code

⭐ 关键点 1：极坐标 → 笛卡尔坐标

⭐ Key Point 1: polar → Cartesian coordinates

// ⭐ 阿基米德螺旋公式：r = a + bθ
const boxSize = 32;                  // 每环宽度
const coilGap = boxSize * 1.2;       // 螺旋间距
const b = coilGap / (2 * Math.PI);   // 半径增长系数
const startRadius = 100;
let theta = (startRadius - 0) / b;   // 起始角度

function pos(t) {                    // t: 角度（弧度）
  const r = 0 + b * t;
  return {
    x: r * Math.cos(t),              // 极坐标转笛卡尔
    y: r * Math.sin(t),
    r
  };
}

⭐ 极坐标 = (r, θ)，笛卡尔 = (x, y)，θ 每增 2π，r 增 b——这就形成"每转一圈外扩一格"的螺旋。如果 b=0，就是普通圆周。

⭐ Polar = (r, θ), Cartesian = (x, y); θ grows by 2π, r grows by b—this produces a “one ring out per loop” spiral. If b=0, it becomes an ordinary circle.

⭐ 关键点 2：动态角度增量

⭐ Key Point 2: dynamic angle increment

// ⭐ 弧长近似相等：Δθ = boxSize / √(b² + r²)
function angleDelta(currentRadius) {
  return boxSize / Math.sqrt(b * b + currentRadius * currentRadius);
}

// 沿螺旋前进 N 天
let t = startTheta;
for (let day = 0; day < 365; day++) {
  const p = pos(t);
  // ...画第 day 天的扇环
  t += angleDelta(p.r);   // 动态加角度
}

⭐ 这条公式是原文档的核心洞察：当半径增大时，相同角度对应的弧长会变长，所以要让 Δθ 随半径增大而减小——这样"每个扇环的弧长"近似相等，视觉上整齐一致。

⭐ This formula is the original document’s core insight: as the radius grows, the same angle spans a longer arc, so Δθ must shrink as r grows—keeping each sector ring’s arc length roughly equal and visually uniform.

⭐ 关键点 3：扇环路径生成

⭐ Key Point 3: sector-ring path generation

// ⭐ 4 关键点：起点外 → 终点外 → 终点内 → 起点内
function segmentPath(t0, t1) {
  const coords = (t, sign) => {
    const r = pos(t).r + sign * coilGap / 2;  // sign=+1 外圈 / -1 内圈
    return [r * Math.cos(t), r * Math.sin(t)];
  };
  const [x0o, y0o] = coords(t0, +1);
  const [x1o, y1o] = coords(t1, +1);
  const [x1i, y1i] = coords(t1, -1);
  const [x0i, y0i] = coords(t0, -1);
  return `M ${x0o} ${y0o} L ${x1o} ${y1o} L ${x1i} ${y1i} L ${x0i} ${y0i} Z`;
}
// d 属性 = 'M ... L ... L ... L ... Z'，4 个 L 描述一个 4 边形

⭐ SVG path 极简：M 移动、L 画线、Z 闭合。手算 4 顶点比用 d3.arc() 灵活（d3.arc 是从圆弧角度算的，对螺旋无法直接用）。

⭐ SVG path in essence: M move, L line, Z close. Computing the 4 vertices by hand is more flexible than d3.arc() (which is built for circular arcs and cannot directly handle a spiral).

5.5 Storyline 时间线（侏罗纪公园）

多角色叙事：每条线 = 一个角色 / 组织 / 进程，y 轴位置 = 聚散关系，时间 = 故事进展。

Multi-character narrative: each line = one character / organization / process, y-position = togetherness vs apartness, time = story progress.

你的原案例

Your Original Case

原 6.2.4 节用《侏罗纪公园》5 个角色（Alan / T-REX / Raptors / Malcolm / Dilophosaurus）做 Storyline 时间线。事件层用红色半透明圆圈标注关键冲突。

Original section 6.2.4 used five characters from Jurassic Park (Alan / T-REX / Raptors / Malcolm / Dilophosaurus) to build a Storyline timeline. The event layer marks key conflicts with semi-transparent red circles.

嵌入陈为教材理论

Embedding Chen Wei's Textbook Theory

  • Storyline 起源：2008 年斯坦福大学 Ogawa & Ma 提出，原本用于电影/学术合作者关系网。
  • Storyline origin: introduced by Ogawa & Ma at Stanford in 2008, originally for movie / academic collaborator networks.
  • 核心：把每个角色/组织/进程抽象为"生命线"，线靠近 = 角色相遇 / 冲突，线分开 = 角色分离。
  • Core idea: abstract each character / organization / process as a “life line,” where lines close = meeting / conflict, lines apart = separation.
  • 3 大元素：
    1. 时间尺度映射：电影时长 → SVG 宽度，x 轴严格按比例对齐
    2. Catmull-Rom 样条：curveCatmullRom.alpha(0.5) 张力系数 0.5，"自然流动"但不"过度弯曲"
    3. 事件层：半透明红圈 + 文字，标注关键转折点
  • Three Key Elements:
    1. Time-scale Mapping: movie duration → SVG width, with the x-axis strictly proportional
    2. Catmull-Rom Spline: curveCatmullRom.alpha(0.5) tension coefficient 0.5, “naturally flowing” but not “over-curved”
    3. Event Layer: semi-transparent red circles + text, marking key turning points
  • 应用场景：电影分析、案件多人时间线、体育比赛互动、项目任务交接。
  • Use cases: film analysis, multi-party case timelines, sports interactions, project task handovers.

为什么 Catmull-Rom 不用 monotoneX？

Why Catmull-Rom instead of monotoneX?

monotoneX 保证"不过度弯曲"但会让线"过于直"，失去叙事的"河流感"。Catmull-Rom 张力系数 0.5 是经验值——既能流动又不震荡。

monotoneX guarantees “no over-curving” but makes lines “too straight,” losing the narrative “river feel”. Catmull-Rom’s 0.5 tension is an empirical value—flows well without oscillating.

⭐ 关键代码

⭐ Key Code

⭐ 关键点 1：每个角色 = 一条 path

⭐ Key Point 1: each character = one path

// ⭐ 时间尺度：0-127 分钟 → 屏幕宽度
const xScale = d3.scaleLinear()
  .domain([0, 127])
  .range([50, width - 50]);

// 每个角色是一组 [time, y] 关键点（手工调 y 实现聚散）
const characters = [
  { name: 'T-REX', color: '#d32f2f', points: [
    {time: 75, y: 280}, {time: 78, y: 130},   // 攻击现场
    {time: 88, y: 200}, {time:120, y: 290}
  ]},
  { name: 'Grant', color: '#1976d2', points: [
    {time:  0, y: 100}, {time: 78, y: 130},   // 与 T-REX 聚拢
    {time:120, y:  50}
  ]}
];

// 路径生成器
const line = d3.line()
  .curve(d3.curveCatmullRom.alpha(0.5))   // 张力 0.5
  .x(d => xScale(d.time))
  .y(d => d.y);

characters.forEach(c => {
  svg.append('path')
    .datum(c.points)
    .attr('d', line)
    .attr('stroke', c.color)
    .attr('stroke-width', 3)
    .attr('fill', 'none');
});

⭐ 用 y 值表达"关系"是关键：T-REX 和 Grant 在 t=78 都画到 y=130，视觉上两条线聚拢= "T-REX 攻击 Grant"。这不是算法生成，是手工叙事设计——但 d3 提供工具让你能这样手工做。

⭐ Using y to encode “relationships” is the key: T-REX and Grant both at y=130 at t=78, so the two lines visually converge = “T-REX attacks Grant.” This isn’t algorithmically generated—it’s manual narrative design, but d3 gives you the tools to do it by hand.

⭐ 关键点 2：事件层（叙事锚点）

⭐ Key Point 2: event layer (narrative anchors)

// ⭐ 事件层：半透明红圈 + 文字标签
const events = [
  { time: 78, x: xScale(78), y: 130, name: 'T-REX 攻击',
    desc: 'T-REX 冲出围栏攻击 Alan & Kids 的车' },
  { time: 48, x: xScale(48), y: 320, name: 'Nedry 事件',
    desc: 'Dilophosaurus 攻击 Nedry' }
];

const eventLayer = svg.append('g').attr('class', 'event-layer');

eventLayer.selectAll('g.event')
  .data(events).enter().append('g')
  .attr('class', 'event')
  .style('cursor', 'pointer')
  .on('mouseenter', (e, d) => showTip(`${d.name}\n${d.desc}`))
  .each(function (d) {
    // 半透明背景圈
    d3.select(this).append('circle')
      .attr('cx', d.x).attr('cy', d.y).attr('r', 20)
      .attr('fill', 'rgba(255,0,0,0.15)');
    // 文字
    d3.select(this).append('text')
      .attr('x', d.x).attr('y', d.y - 9)
      .attr('text-anchor', 'middle')
      .attr('font-size', 10).attr('font-weight', 600)
      .attr('fill', '#cc0000')
      .text(d.name);
  });

⭐ 事件层与线层解耦：线层表达"关系流动"，事件层表达"叙事锚点"。这种双层结构是 Storyline 的标准设计——可分别动画、可独立筛选。

⭐ Decouple event layer from line layer: the line layer expresses “relationship flow,” the event layer expresses “narrative anchors.” This two-layer structure is the standard Storyline design—each can be animated or filtered independently.

⭐ 关键点 3：alpha(0.5) 张力系数

⭐ Key Point 3: alpha(0.5) tension coefficient

// d3.curveCatmullRom.alpha(t) - t ∈ [0, 1]
// t=0: 接近 linear（接近直线）
// t=0.5: 标准 Catmull-Rom（推荐）
// t=1.0: 接近 cardinal（高度曲线化）
d3.line().curve(d3.curveCatmullRom.alpha(0.5));

⭐ 选 0.5 是经验值：比 0 更"软"（看起来有故事感），比 1.0 更"稳"（不会过山车）。做时间叙事就用 0.5；做科学曲线拟合就用 0.2-0.3（更接近数据）。

⭐ 0.5 is an empirical value: softer than 0 (looks narrative), steadier than 1.0 (no roller-coaster). Use 0.5 for time-based narratives; use 0.2–0.3 for scientific curve fitting (closer to data).
