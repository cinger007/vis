## 1.1 Data Generation

### Your Original Case

This chapter uses the new student data (新生数据) of the China University of Petroleum (East China) Class of 2025. The data was synthesized by the DeepSeek large model, containing 80 records:

```
序号、姓名、性别、生日、年龄、班级、籍贯、民族
```

### Embedded Theory: The Credibility Boundary of AI-Synthesized Data

| Dimension | Meaning | Data generated by DeepSeek |
|---|---|---|
| Accuracy | Degree of reflection of the real world | ⚠️ names/places of origin fabricated |
| Completeness | Whether required fields are complete | ✅ all fields present |
| Consistency | Same concept expressed consistently in different places | ✅ fields consistent |
| Timeliness | Data reflects current state | ✅ enrollment year matches |

**The "sampling bias" of AI-synthesized data**: models tend toward "plausible-looking" distributions (ethnicity skewed toward Han, places of origin skewed toward large cities).

### ⭐ Key Code Segment ①: Field Name Mapping

```javascript
// ⭐ 关键点 ①：字段映射 —— 把中文 CSV 列名转英文 JS 变量
const COLUMN_MAP = {
  "序号": "id",
  "姓名": "name",
  "性别": "gender",
  "生日": "birthday",
  "年龄": "age",
  "班级": "class",
};
```

**Why not use Chinese keys?**
- JS engines have poor tolerance for Chinese identifiers (older browsers throw errors)
- Backends, JSON, and URL encoding may all introduce garbled characters
- IDE autocomplete, search, and refactoring tools have inconsistent support for Chinese

**Best practice**: use human-readable Chinese names in CSV, and unified English variables inside JS.

### ⭐ Key Code Segment ②: Type Conversion Function

```javascript
// ⭐ 关键点 ②：类型转换 —— 用户原文「推荐方式」
function transformRow(d) {
  return {
    id:       +d["序号"],              // 一元 + 把字符串转 Number
    name:     d["姓名"].trim(),       // trim() 去掉首尾空白
    birthday: new Date(d["生日"]),   // 字符串 → Date 对象
    age:      +d["年龄"],
    class:    d["班级"].trim(),
  };
}
```

**Explanation of key points**:
- `+d["年龄"]` is the unary plus operator, the fastest way in JS to convert a string to a number
- `new Date(str)` parses ISO-format dates, but has poor compatibility with `"2007/8/15"`; use `d3.timeParse("%Y-%m-%d")` as a fallback
- **Pitfall**: without `trim()`, the trailing space in "软件工程1班 " will cause errors in later filtering/aggregation

### ⭐ Key Code Segment ③: Passing the row Callback Directly as the Second Argument of d3.csv

```javascript
// ⭐ 关键点 ③：一行完成加载 + 转换
const data = await d3.csv("data/newstudent.csv", transformRow);

// 验证类型确实转换了：
console.log(typeof data[0].age);              // "number"
console.log(data[0].birthday instanceof Date); // true
```

**Why this line matters**:
- `d3.csv` is an asynchronous function and must be `await`ed
- The row callback in the second argument is called **immediately after each row is parsed** — saving memory compared to "first `await d3.csv()` then `.map()`"
- **The meaning of asynchronous loading**: it does not block page rendering, so users can keep interacting

## 1.2 Data Definition

### Your Original Case (DIKW Pyramid)

| Layer | Original text | Question answered |
|---|---|---|
| Data | Raw, discrete observations | — |
| Information | Data that has been processed, organized, and given context | Who / What / When / Where |
| Knowledge | Further refinement and understanding of information | How |
| Wisdom | Applying knowledge to make wise judgments and strategic decisions | Why / What should be done |

### Embedded Theory: Where Visualization Sits in the DIKW Pyramid

**Key insight**: visualization mainly lifts **Data up to Information**, and in a few scenarios up to **Knowledge**, but it is hard to cross over to Wisdom.

- ✅ Data → Information: "translating" tables into readable graphics (line charts, bar charts, heatmaps)
- ⚠️ Information → Knowledge: pattern discovery requires statistical models as aid (machine learning)
- ❌ Knowledge → Wisdom: decisions and strategy exceed the capability of visualization

**Rowley (2007) criticism**: DIKW is an over-simplified hierarchical model. But as a teaching scaffold it remains the most valuable.

### ⭐ Key Code Segment ①: SVG Pyramid Path

```javascript
// ⭐ 关键点 ①：trapezoid 路径 —— 从上到下 4 个点的连线
const topW = 60, botW = 120;
const yTop = 20, yBot = 100;
const path = `
  M ${cx - topW/2} ${yTop}
  L ${cx + topW/2} ${yTop}
  L ${cx + botW/2} ${yBot}
  L ${cx - botW/2} ${yBot}
  Z
`;
```

**Explanation of key points**:
- The SVG path commands `M` (moveto), `L` (lineto), `Z` (close) are the 3 most commonly used
- Template literals `${...}` embed JS variables directly, more readable than string concatenation
- **Practice**: for complex shapes use `d3.symbol()` (built-in ★●▲); writing your own path is error-prone

### ⭐ Key Code Segment ②: Interactive Highlight (Events)

```javascript
// ⭐ 关键点 ②：选择集绑定事件 —— 注意 function 而非箭头函数
const g = svg.append("g")
  .style("cursor", "pointer")
  .on("mouseover", function () {       // ⚠️ 必须 function，不能箭头函数
    d3.select(this).select("path")      //    因为要用 this 访问当前元素
       .transition().duration(150)
       .attr("fill", d3.color(layer.color).brighter(0.5));
  })
  .on("click", () => showDetail(layer));  // 这里箭头函数 OK（不用 this）
```

**Explanation of key points**:
- **You must use `function()` instead of an arrow function** — because D3 callbacks use `this` to access the current element, and an arrow function captures the outer `this`, which fails
- This is the most common pitfall in D3
- `transition().duration()` is D3's built-in animation API, even cleaner than jQuery

## 1.3 Data Attributes

### Your Original Case (3 Major Categories)

| Category | Example | Description |
|---|---|---|
| Categorical | Name, gender | No ordinal relationship |
| Ordinal | Class, degree | Has order, no spacing |
| Numerical | Age, exam score | Quantitative |

### Embedded Theory: Stevens' Measurement Scales (1946) — 4 Categories

Four categories finer than your original text:

| Category | Allowed operations | Typical example | Corresponding to your original |
|---|---|---|---|
| **Nominal** | equivalence / non-equivalence | Name, gender | Categorical |
| **Ordinal** | + > < | rank, class number | Ordinal |
| **Interval** | + addition/subtraction | temperature (°C) | — |
| **Ratio** | + addition/subtraction/multiplication/division | age, price | Numerical |

**Key distinction**: the interval scale has no "true zero point" (0°C is not "no temperature"); the ratio scale has a true zero point (0 yuan = no money).

### Embedded Theory: Mackinlay's Visual Channel Ranking (1986)

| Tier | Channel | Suitable attribute |
|---|---|---|
| **Quantitative** | position, length, angle | Ratio / Interval |
| **Ordered** | brightness, density, saturation | Ordinal |
| **Categorical (qualitative)** | hue, shape | Nominal |

**Core finding**: position is the strongest quantitative channel; hue is the strongest categorical channel. **Mismatch → information loss**.

### ⭐ Key Code Segment ①: Scale Selection

```javascript
// ⭐ 关键点 ①：scale 选型 —— 属性 ↔ 通道的映射
// 比率型数据 → scaleLinear（连续定量）
const x = d3.scaleLinear().domain([0, 100]).range([0, 800]);

// 名义/序数型数据 → scaleBand（离散分类）
const x = d3.scaleBand()
  .domain(["软件1班", "软件2班", "数据1班"])
  .range([0, 800]);
```

**Explanation of key points**:
- `domain()` is the data domain (input), `range()` is the value range (output pixels)
- **Choosing the wrong scale is the most common mistake beginners make**: using scaleLinear for categorical data yields meaningless intermediate values (e.g., 0.5 class)
- **Memory aid**: use Linear for continuous quantitative, Band for discrete categorical, Point for ordinal

### ⭐ Key Code Segment ②: Colormap Selection

```javascript
// ⭐ 关键点 ②：颜色映射 —— 顺序 vs 定性 vs 发散
// 顺序型（顺序有意义）→ Viridis / Blues —— CVD 友好
const color = d3.scaleSequential(d3.interpolateViridis);

// 定性型（无顺序）→ schemeTableau10
const color = d3.scaleOrdinal().range(d3.schemeTableau10);

// 发散型（有中点）→ RdBu
const color = d3.scaleDiverging(d3.interpolateRdBu);
```

**Explanation of key points**:
- Viridis is the benchmark sequential colormap, color-vision-deficiency (CVD) friendly and perceptually uniform
- **Common mistake**: encoding values with the rainbow `interpolateRainbow` — neither CVD friendly nor free of false boundaries
- **When to use diverging**: data with a "midpoint" (positive/negative, temperature vs. average)

## 1.4 Data Transformation

### Your Original Case (8 Functions)

| # | Function | Purpose |
|---|---|---|
| 1 | `map(iterable, mapper)` | similar to Array.map |
| 2 | `reduce(iterable, reducer, init)` | similar to Array.reduce |
| 3 | `cross(...iterables, reducer)` | Cartesian product |
| 4 | `merge(iterables)` | merge into a flat array |
| 5 | `pairs(iterable, reducer)` | adjacent element pairs |
| 6 | `transpose(matrix)` | matrix transpose |
| 7 | `zip(...arrays)` | combine element-wise |
| 8 | `filter(iterable, test)` | similar to Array.filter |

### Embedded Theory: Functional Data Flow

Common characteristics of these 8 functions:
- ✅ **Immutable**: input unchanged, returns a new array
- ✅ **Pure function**: same input → same output
- ✅ **Chainable**: the return value is an array, which can feed the next transformation

**Why functional?** Reasonable (each layer independently testable), parallelizable (map/reduce are naturally parallel), cacheable (pure functions can be memoized).

**The embryonic form of an OLAP data cube**: `transpose` converts wide/long formats, `group + rollup` performs slice/dice/drill-down.

### ⭐ Key Code Segment ①: map / reduce Chained Composition

```javascript
// ⭐ 关键点 ①：函数式数据流 —— map 后接 filter 再 reduce
const avgAge =
  students
    .filter(s => s.gender === "男")     // ① 过滤男生
    .map(s => s.age)                    // ② 提取年龄
    .reduce((sum, a) => sum + a, 0)     // ③ 合计
  / students.filter(s => s.gender === "男").length; // ④ 求平均
```

**Explanation of key points**:
- Each step of the chained call returns a new array and does not modify the original
- **Compared with imperative**: imperative needs 4 temporary variables + a for loop; functional does it in one line
- **Performance trade-off**: each map/filter creates a new array, causing performance overhead for very large arrays (significant only at the millions level)

### ⭐ Key Code Segment ②: cross (Cartesian Product)

```javascript
// ⭐ 关键点 ②：cross —— 笛卡尔积
const genders = ["男", "女"];
const majors  = ["软件工程", "数据科学"];
const combos  = d3.cross(genders, majors);
// → [["男","软件工程"], ["男","数据科学"], ["女","软件工程"], ["女","数据科学"]]
```

**Explanation of key points**:
- Cartesian products are commonly used in "pairwise combination" analysis (e.g., counting people by gender × major)
- The second-argument reducer is optional, used to "merge" the two elements
- **Extension**: the size of the Cartesian product of n arrays is the product of each array's length

### ⭐ Key Code Segment ③: group / rollup (Aggregation)

```javascript
// ⭐ 关键点 ③：group 与 rollup —— 层次聚合
// group 返回 Map（保留所有元素）
const byClass = d3.group(students, s => s.class);

// rollup 返回 Map（每个 key 只保留聚合值）
const countByClass = d3.rollup(
  students,
  v => v.length,         // reducer
  s => s.class           // key 提取函数
);
```

**Explanation of key points**:
- `group` vs `rollup` is the difference between "group and keep" vs "group and aggregate"
- The second argument of `rollup` is the reducer function (here it takes the length)
- A later chapter, `doc-02`, will use `rollup` in detail for tree-shaped data

## 1.5 D3 Data Selectors

### Your Original Case (6 Methods)

| Method | Returns |
|---|---|
| `d3.select` | single element |
| `d3.selectAll` | a selection of multiple elements |
| `selection.select` | the first among the descendants of each selected element |
| `selection.selectAll` | all among the descendants |
| `selection.selectChild` | the first direct child element |
| `selection.selectChildren` | all direct child elements |

### Embedded Theory: The Data-Join Three-State Model

The core of D3 is **Data-Join**: "binding" a data array to DOM elements. When the data changes:

- New data > old data: the extras enter **enter** (need to append)
- New data = old data: the original elements enter **update** (need attribute changes)
- New data < old data: the surplus elements enter **exit** (need to remove)

### ⭐ Key Code Segment ①: The .join(enter, update, exit) Three States

```javascript
// ⭐ 关键点 ①：D3 v5+ 的 join() API —— 优雅处理三态
const circles = svg.selectAll("circle")
  .data(currentData)
  .join(
    enter  => enter.append("circle").attr("fill", "green"),  // enter
    update => update.attr("fill", "cyan"),                    // update
    exit   => exit.remove()                                   // exit
  );
```

**Explanation of key points**:
- The three callbacks of join are invoked at the enter / update / exit stages respectively
- More concise than the v3 `enter().append()` + `exit().remove()` style, and less error-prone logically
- **Analogy**: React's diff + patch — same idea, but React does it for you, while D3 makes you write the transform functions yourself

### ⭐ Key Code Segment ②: The Key Function Preserves Identity

```javascript
// ⭐ 关键点 ②：key 函数 —— 元素身份的稳定器
// ❌ 不带 key：数据顺序变化 → 所有元素都"update"，过渡动画错乱
svg.selectAll("circle").data(newData);

// ✅ 带 key：用唯一字段绑定身份
svg.selectAll("circle").data(newData, d => d.id);

// 同样的逻辑用 React 描述：key={item.id}
```

**Explanation of key points**:
- **The key function is the soul of D3 animations**
- Without a key, D3 binds identity by index: reordering data causes "all elements to change position"
- With a key, each circle knows its own id; on reorder only cx changes, and the transition animation is natural
- **Analogy**: exactly the same idea as React's `key={item.id}`

### ⭐ Key Code Segment ③: select vs selectAll

```javascript
// ⭐ 关键点 ③：选择器的核心区别
// select：返回 1 个元素（第一个匹配）；数据绑定只对这一个元素
const title = d3.select("#title");

// selectAll：返回多个元素；数据绑定按顺序一一对应
const bars = d3.selectAll(".bar").data(values);
```

**Explanation of key points**:
- `select` is for "operating on a single element", `selectAll` is for "binding data in bulk"
- **Common mistake**: when using `selectAll(".bar")` to bind data to an array, the number of elements and the number of data items must match, otherwise there is "empty space" or "overflow"
- **Best practice**: first use `selectAll` to create placeholder elements (possibly empty), then `.data().join(...)`
